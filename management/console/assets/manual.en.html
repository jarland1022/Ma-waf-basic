Ma-WAF User Manual

This guide covers the management console (default https://<IP>:8443/). The data plane is Nginx + ModSecurity + OWASP CRS.

2. Login & security

  • Default admin URL: https://<device-IP>:8443/ (trust or continue past the self-signed cert).
  • Default account: admin (change the password and enable TOTP / bcrypt in production).
  • Management plane access is limited to localhost and private networks by default (see Nginx allow list).

4. Sites

Web sites

Create/edit reverse-proxy sites: domain, listen port, upstream, WAF on/off, rate limits, JS Challenge, Geo, API prefixes, etc. Saving runs Nginx config test and reload.

Site discovery

Parses Host values from access logs against managed sites; unprotected domains can be turned into site drafts in one click.

5. Policy & rules

  • Security policy: Preset profiles (loose / normal / strict / debug / emergency) that can be applied to sites.
  • Protection rules: Enable/disable custom rules, virtual patches, and rule packs.
  • Exceptions: Allow false-positive URLs/rules.
  • Heavy-security mode: Raises CRS paranoia and keeps the engine On (reason is audited).
  • Engine mode: On (block) / DetectionOnly / Off.

6. Monitoring & reports

  • Security events: Host, status, request/response length, attack fields; use Details for rule hits and POST body preview.
  • Reports: Attack trends, Top IP/rules; export CSV / compliance HTML.

7. Objects

  • Address book: Reusable IP/CIDR objects that can be applied to black/white lists.
  • IP / Geo lists: Black/white lists and country blocks (requires GeoIP MMDB and module).

8. System ops

  • System & signatures: Host info, CRS/Geo/intel status; local rule-pack upgrades on the page.
  • PKI: Generate management-plane admin.crt / admin.key.
  • System ops: Host metrics, HA status, alert webhook, auto-block, etc.
  • Troubleshooting: One-click health checks (nginx -t, certs, console files, ports, disk), fix certs / Reload, error log tail and FAQ tips.
  • License: Hardware fingerprint and .lic import.

9. Local rule upgrades

Path: System → System & signatures or System → Signature upgrades.

  1. Prepare a .tgz / .tar.gz with custom/*.conf and/or rules/*.conf.
  2. Optionally upload a matching .sig (with conf/update-pubkey.pem).
  3. Check “promote and reload immediately”, then upgrade.
sudo ./scripts/update_rules.sh --offline /path/to/rules_bundle.tgz

# Build & install API
sudo ./scripts/install_api.sh

sudo ./scripts/sync_console.sh

# Nginx test & reload
sudo /usr/local/nginx/sbin/nginx -t && sudo /usr/local/nginx/sbin/nginx -s reload

11. FAQ

Console won’t open / nginx -t missing cert

Generate certs under System → PKI, or run fix_runtime.sh, then nginx -s reload.

Data plane returns 502

WAF/Nginx entry is up, but the upstream app is down. Check the site upstream and backend process.

Attack probes are not blocked

Confirm SecRuleEngine is On (DetectionOnly only audits) and the site has ModSecurity enabled.

UI changes don’t appear

Sync management/console → share/console, then hard-refresh (Ctrl+F5).
